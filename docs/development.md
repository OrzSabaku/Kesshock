# 開発ガイド

## 構成

```text
cmd/kesshock/
  main.go              # 引数・標準入出力の受け渡しと終了コード
internal/cli/
  cli.go               # コマンドの振り分け
  args.go              # 引数の解析と検証
  help.go              # ASCIIロゴとヘルプ
  login.go, otp.go     # パスワード認証とメールOTP認証
  credentials.go       # .envの読み込みと対話入力の選択
  terminal.go          # 行入力とパスワードの非表示入力
  status.go            # 保存HTML・サーバーからの状態表示
  display.go           # ASCIIによる申請状態の描画
  apply.go             # 変更確認・競合検出・送信後の照合
  schedule.go          # 日付ごとの申請状態と変更の検証
  form.go, html.go     # フォームと入力欄の解析・エンコード
  client.go, url.go    # HTTP通信と送信先の制限
  cookies.go           # Cookieの復元・保存
  forget.go            # 保存済みCookieの削除
  *_test.go            # 各処理の回帰テスト
```

実行入口には業務処理を置かず、`cli.Run`に渡します。関連する処理は同じパッケージ内でファイルを分けています。この規模では、細かなパッケージ間の公開APIや変換処理を増やすより、処理の流れを追えることを優先します。

## ビルドと検証

リポジトリのルートで実行します。

```sh
go test ./...
go vet ./...
go test -race ./...
go build -buildvcs=false -o kesshock ./cmd/kesshock
./kesshock --help
```

テストは模擬通信を使います。実サイトへのログイン、OTPメールの送信、申請の登録は行いません。テスト用の認証情報とHTMLも架空のものです。

`fakeNetwork`はプロセス共通のHTTPトランスポートを差し替えます。一部の認証テストは作業ディレクトリも変更するため、これらのテストでは`t.Parallel()`を使わないでください。Cookieはテスト用の一時ディレクトリに保存します。

## 変更時に守る条件

- 同じ名前のフォーム項目と、その順序を保持します。日付と備考は位置で対応しているため、送信前に名前で並べ替えないでください。
- 変更対象と備考をすべて検証してからフォームを書き換えます。検証エラーで元のフォームを部分的に変更しないでください。
- `--yes`は確認入力だけを省略します。`--apply`の判定、最新フォームでの競合検出、送信後の照合は省略しません。
- POSTは自動再送しません。通信エラーでもサーバー側では登録が済んでいる可能性があります。
- OTP入力画面やHTTP 200だけではログイン成功としません。保護された登録フォームを取得できたことを確認します。
- パスワード、OTP、応答HTMLをログやエラーに含めません。Cookieの保存形式と旧保存先は、既存セッションとの互換性を保ちます。
- HTMLの`maxlength`はUTF-16コード単位で数えます。Goのバイト数やルーン数への置き換えで、絵文字の扱いを変えないでください。

## コメントの方針

公開関数とパッケージには役割を説明するGoのドキュメントコメントを付けます。内部処理では、コードを言い換える説明より、判断の理由、サイト固有の制約、変更すると失われる保証を残します。名前と関数の分割で伝わることにはコメントを重ねません。
